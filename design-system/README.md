# Cassie Liang Design System

This is the visual and editorial operating system for Cassie's public work: portfolio pages, project case studies, product landing pages, and small utility interfaces.

It is for a builder who works across AI, backend systems, iOS, and the browser—and who cares that technology leaves people with more clarity and agency, not less.

## The north star

**Make systems feel legible, trustworthy, and alive.**

The work should feel like an engineering notebook edited by someone with taste: rigorous enough to earn technical trust, warm enough to show why the work matters. It is neither startup marketing nor an art-school scrapbook.

## Quick start

1. Read [brand-dna.md](brand-dna.md) before making visual or copy decisions.
2. Use [tokens.css](tokens.css) rather than introducing ad-hoc color or type values.
3. Choose a page recipe from [references/page-recipes.md](references/page-recipes.md).
4. Compose only from the contracts in [references/component-contracts.md](references/component-contracts.md).
5. Run [references/review-checklist.md](references/review-checklist.md) before sharing.

The portfolio's `index.html` and `en/index.html` already consume the canonical tokens.

## What was redesigned

The previous visual language had several good instincts—warm paper, a terminal, graceful serif type, direct writing—but its four pastel project colors competed for attention. This system keeps the contrast and personality while assigning every accent a semantic job. A page now has one dominant emotional mode; a component has one accent; the content does the convincing.

## Reference and attribution

The workflow structure was inspired by ESTHER's [Personal Design Skill](https://github.com/esthersjw/esther-design-system): express personal taste as constraints an AI can follow. This is an original system written for Cassie's work; no reference templates or component code were copied.
